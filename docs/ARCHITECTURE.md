# ClauseGraph Verify architecture

One Next.js frontend calls a modular FastAPI API; one worker imports the same Python modules. PostgreSQL stores session snapshots, versioned document/rule data, financial events, scenario runs and leased jobs. SQLite is an explicitly local development fallback. Private local files or private DigitalOcean Spaces hold originals. Production accepts PostgreSQL via DATABASE_URL, including Tiger Data; a Tiger Data service has not been live-verified here.

## Processing pipeline
Upload validates PDF/text/CSV size/type, hashes bytes per session and records native page text with quote offsets. Worker extracts typed candidates via Nemotron Lightning. Consequential candidates receive a separate Nemotron Nano Omni evidence check by default; Gemini is an explicit `EVIDENCE_PROVIDER=gemini` alternative. Native text absence enables consent-gated vision. For NVIDIA, unreadable pages are locally rendered to bounded JPEGs in a killable subprocess; at most four original source pages per request, preserving page numbers and native text on mixed PDFs. Exact quote/amount validation precedes human review. Same-family model agreement is not independent proof and never marks a rule reviewed. Provider failures surface on jobs; there is no silent provider or fixture fallback.

The browser supplies `consent_provider` with uploads, checked against current server configuration before storage. New extraction jobs bind consent to the selected evidence provider; changing it before execution fails the job without sending document data. Legacy uploads that omit this optional field consent to the currently configured provider; legacy queued jobs predate this switch and used the old NVIDIA-and-Google consent notice. Re-upload with refreshed consent to retry after changing providers.

Reviewed rules compile into an allowlisted DSL: add an evidenced event, remove a specified payment, shift a specified event, or accelerate an existing obligation. Conditions support eq/gte/lte/exists, but unresolved facts block compilation. Graph edges are requires/triggers/excludes/supersedes/supports; NetworkX checks dependencies/cycles and contradictions. Extraction does not authorize execution.

## Canonical contracts and endpoints
`backend/clausegraph/schemas.py` owns API shapes; FastAPI OpenAPI is exported to `docs/openapi.json` and openapi-typescript generates `frontend/src/lib/api-types.ts`. Frontend imports aliases from generated schemas. All money is integer cents, all dates ISO dates. Evidence offsets are page-local, end-exclusive. Every PlanResult persists its typed PlanRequest as `assumptions`, so scenario history and restored UI controls disclose the inputs that produced the result.

Endpoints use `/api`: POST `/sessions` creates an empty session (body `{demo: bool}`; UI explicitly requests synthetic demo); bearer token returned as session_id. GET `/workspace`, GET `/history` (latest 30 private PlanResults), POST `/demo/reset`, POST `/intake`, POST `/plan` (PlanRequest -> PlanResult), POST `/documents` multipart file + consent bool (UploadResponse), GET `/documents/{id}/original?version=N` (authenticated attachment), DELETE `/documents/{id}`, PATCH `/rules/{id}` (RuleReview -> Workspace), GET `/jobs/{id}`, GET `/jobs/{id}/events` SSE, POST `/actions/{id}/draft` (DraftResponse), GET `/evidence/export` Markdown attachment, GET `/providers`, POST `/providers/smoke`, DELETE `/session`. All except health/session creation require `Authorization: Bearer <session_id>`. Session IDs are unguessable bearer credentials; local UI stores only this token. Audio endpoints POST `/audio/transcribe` (file -> text/facts_confirmed:false), POST `/audio/checklist` (-> audio/mpeg), never auto-apply transcription. CORS origins allowlisted.

Same-name changed uploads retain versioned originals and supersede obsolete extraction jobs. Deleting a source purges its original, extracted wording, rules, jobs and historical narratives; known expenses retain amount/date/essential flags with generic titles and dangling provenance, forcing unresolved review instead of making debt disappear. Session deletion removes all session records and originals. Workspace/history chart series read persisted daily-balance rows. The bounded plan cache is keyed by session, input revision and scenario assumptions.

## Bounded verification

`verify_plan(scenario, rules, plan, request) -> VerificationResult` in `verification.py` holds the saved actions/dates fixed. `POST /api/verify` requires the current saved plan ID and input revision; it never optimizes or replaces the plan. `GET /api/verifications` returns the latest 30 private reports, including persisted daily points. Saving locks/rechecks revision and active-plan identity. Ordinary revisions leave explicitly historical reports; source/session deletion and demo reset purge their narratives and points.

Canonical uncertainty contracts discriminate `income_date` (event, inclusive earliest/latest), `income_amount` (event, inclusive integer-cent bounds), and `approval` (rule/action, finite approved/denied/pending outcomes). Every dimension has a unique ID and explicit `user_assumption` rationale. Bounds are never inferred or presented as reviewed-source ranges. Dimensions form an independent Cartesian product; no probabilities/correlations are claimed. Actual/historical events cannot vary. Reports include inherited nominal assumptions as well as new bounds.

Finite exhaustive model checking reuses `_prepare_ledger`, `_gates`, evidence checks, `_action_changes`, `_materialize` and `simulate`; CP-SAT candidate deltas already share `_action_changes`. No separate Z3 arithmetic model or new solver dependency is introduced. Income assumptions relax only the explicitly varied fields. Source identity/direction/review/conditions remain gates; approval outcomes apply to isolated copies. Pending/denied never authorize a selected action and recorded decisions never change.

Properties cover nonnegative daily closing cash, essential obligations/services, authorized/evidenced/in-window/dependency-valid actions, unique event/obligation transformations and retained future debt. Unauthorized schedules report failures with no permitted cash simulation. Unresolved ledger facts prevent SAFE. A counterexample contains exact assignment, earliest failing date, balance when meaningful, failure/action/rule details, and the materialized event trace. Complete enumeration selects the earliest failure with deterministic lexicographic tie-breaking. Worst-balance assignment is reported separately and may differ.

Mixed-radix enumeration avoids allocating enormous ranges. Default budget: 5 seconds and 10,000 cases; API maximum: 10 seconds, 10,000 cases, 8 dimensions. The deadline is cooperative between cases, not a subprocess hard kill. SAFE requires complete coverage and resolved facts; UNSAFE requires a concrete violated property; otherwise UNKNOWN. Reports expose EXHAUSTED/TIME_LIMIT/CASE_LIMIT/INVALID_MODEL, runtime, counts, coverage and worst-case proof flags. Partial minima are observations, never proven worst cases. Guarantees cover only the displayed model and `[start,end)` horizon, excluding intraday liquidity, hidden obligations and later dates.

Migration003 adds `verification_runs` and `verification_points` to the existing SQLite/PostgreSQL-compatible store. No Timescale feature or unmeasured performance claim is made. General robust synthesis is deferred. `scripts/verify_demo.py` instead uses a proven negative nominal optimum at one allowed assignment to prove no robust safe schedule exists, and verifies a fixed schedule with explicitly hypothetical extra opening cash to establish a tight bounded cash diagnostic.

## Solver
CP-SAT selects actions and execution dates within deadlines, approved/reviewed evidence, dependency ordering, exclusions, essential-service constraints. Lexicographic objectives: seek nonnegative daily balances; maximize minimum daily balance; minimize fees then burden and execute deterministically. Run phases within a bounded deadline, expose FEASIBLE vs OPTIMAL honestly. If nonnegative impossible, maximize minimum to calculate minimum extra cash diagnostic. Any forced forbidden action returns unresolved/infeasible with explanation. Action effects on a shared event conflict unless modeled explicitly; avoid double counting. Date boundaries use [start,start+horizon) and retain all future obligations. Conditional assumptions can only affect a clearly labeled conditional result. Persisted approvals require explicit review endpoint. Plans invalidated by uploads/reviews/deletion/intake and revision checks guard worker results.
